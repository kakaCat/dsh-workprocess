## 二、降级预期（设计 ⑤）

| 情形 | 怎么造 | 应看到 |
| --- | --- | --- |
| 无流程 | **新开一个会话**（还没有 workprocess 流程） | 「阶段」条目**整条不出现**——没有 0/0、没有报错、没有灰条 |

## 五、重启后看不到卡片？排查顺序（wt:verify:2 预备）

> **先排除宿主升级导致的"整栈未装载"**：若工具 / 卡片 / `/work` 命令**一起**消失且重启无效，
> 判据与修法见 [`docs/workprocess-dsh-upgrade.md`](./workprocess-dsh-upgrade.md)。本节假设宿主没升级，
> 只是浏览器半或数据面的问题。

1. **确认真重启了**：宿主必须整个退出再开（扫描缓存按 boot 算，热重载插件行不重扫 manifest）。
2. **浏览器半加载报告**：宿主里跑 `cordis_inspect what:"temporary"`，看有没有 `workprocess` 的报错
   （注册失败/未注册都会点名）。**这一步只能人跑**（我够不到宿主工具面）。
3. **网络面板**：DevTools 里看 `/plugins/workprocess/client.js?rev=…` 请求——200 且返回的是我们的
   产物（文件头注释 `workprocess 浏览器半`）才算被扫到；404/401 都是没加载。
4. **dock 槽**：若产物 200 但界面上没有，看同槽其它条目（todo/goal/queue）在不在——在 = 注册成功
   但渲染了空（无流程时整条不渲染是**正确行为**；本会话有流程不该空）；都不在 = 槽本身没渲染。
5. **数据面**：DevTools 里看 `/workprocess/api/stages?scope=<本会话id>` 应 200 且 JSON 里有
   `process.stages[]`；404 `no-process` = 数据面活了但读的是别的 scope（检查请求里的 scope 是不是会话 id）。
